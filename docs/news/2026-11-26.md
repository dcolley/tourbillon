# Tourbillon weekly changelog — 26 November 2026

**Reporting window:** 12 November 2026, 10:20 through 26 November 2026, 16:25 GMT (Europe/London). This picks up where the [12 November entry](2026-11-12.md) ended, so nothing is reported twice.

A focused fortnight: task-list status notices now reach Assistant Chat and arrive live on an open page, issue links became readable, and a CI hang was fixed. These changes are merged into `main`; this does not mean that every installation has upgraded.

## Concierge task-status notices reach Assistant Chat

When a chat task changes state — done, needs input, or started — Assistant Chat now shows one compact notice for that transition. Previously these changes were only visible in the task list itself, and the chat stayed silent.

- Notices reach an open chat page live, without a reload. If the chat is in the middle of a reply, the notice waits for that reply to finish rather than interrupting it.
- The notices fire when agents update or complete tasks through their tools, not only through the background runner. When both paths report the same transition, they collapse into a single notice rather than duplicating it.
- A "needs input" notice shows the question that needs an answer. Once the same task resumes, the older waiting notice is superseded by the newer status.

This was verified against a certification suite that runs the real services rather than mocks, and the covering test files are pinned into CI so they cannot silently drop out. The feature is newly shipped this week, so treat it as fresh: broader day-to-day use is still being observed.

Source: [#367](https://github.com/dcolley/tourbillon/pull/367) (refs [#363](https://github.com/dcolley/tourbillon/issues/363)).

## CI stability: test runs no longer hang at exit

One test helper kept a background connection open after all its checks had finished, which could hold the test process alive and stall the CI job instead of letting it complete. The connection now releases the event loop whenever it is not actively publishing, so the run exits cleanly. No product behaviour changes in this item; it shipped as part of the same pull request as the notices above.

Source: [#367](https://github.com/dcolley/tourbillon/pull/367).

## Friendlier issue links

Issue URLs now use readable keys such as `TOUR-590` instead of long unique ids. Links generated across the app — the board, issue tables, project and goal pages, approval cards, the activity view and search results — all use the readable key.

Existing id-based links keep working: bookmarks, saved links and API callers that use the old form continue to resolve to the same issue. If a company changes its issue prefix, old links keep resolving to the issues they pointed at, while new issues pick up the new prefix.

Source: [#366](https://github.com/dcolley/tourbillon/pull/366) (fixes [#286](https://github.com/dcolley/tourbillon/issues/286)).
