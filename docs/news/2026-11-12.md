# Tourbillon weekly changelog — 12 November 2026

**Reporting window:** 7 November 2026, 09:40 through 12 November 2026, 10:20 GMT (Europe/London). This picks up where the [7 November entry](2026-11-07.md) ended, so nothing is reported twice.

This week was a smaller, quality-focused week: two security fixes, task-progress notices that now reach the chat thread where the task started, and stricter CI around both. This entry covers changes merged into `main`; it does not imply that every installation has upgraded.

## Security fixes

### Agent write routes no longer trust a caller-supplied run id

On the agent routes for issue checkout, issue comments and issue updates, the run-id request header is no longer accepted as the acting run. If the header is absent, the run is taken from the agent's signed token. If it matches the token, nothing changes. Any other value is rejected with a `403 run_id_mismatch` before any issue is read, locked, commented on or changed. Issue updates now also record the authenticated run instead of leaving it empty when the header is missing.

Board users are unaffected, and chat-originated agent calls keep working.

Source: [#352](https://github.com/dcolley/tourbillon/pull/352) (refs [#114](https://github.com/dcolley/tourbillon/issues/114)).

### Vault OAuth connections are bound to the right company and can only be used once

The OAuth flow used to connect an agent's vault credentials now ties each sign-in attempt to the company that started it, expires after ten minutes, and is consumed exactly once before the provider exchange happens. Replayed, expired, mismatched or cross-company callbacks are refused before any credential exchange takes place. Archived agents can no longer start a connection.

Source: [#355](https://github.com/dcolley/tourbillon/pull/355) (refs [#112](https://github.com/dcolley/tourbillon/issues/112)).

## Task-progress notices reach the originating chat thread

When a task started from a chat makes progress, its notice is now delivered to the chat thread where the task was started, without switching or re-pinning any other conversation. If that thread is idle the notice is delivered straight away; if it is busy, the notice waits behind that thread's own run rather than interrupting an unrelated one.

This change was accepted against a certification harness that runs the real services (database, queue, notification bridge and agent controller) rather than mocks, and CI now requires that harness to run fully. It is newly shipped this week, so treat it as fresh: broader day-to-day use is still being observed.

Last week's entry said automatic task notifications were not yet verified end to end. This change is the first to carry real-services evidence for that path, for notices routed to the originating thread.

Source: [#354](https://github.com/dcolley/tourbillon/pull/354).

## CI and test hardening

- The task-notification CI job now fails if the real-services certification run cannot execute, instead of quietly passing with missing evidence.
- New database-backed tests cover cross-company OAuth requests, tampered sign-in state, and secure-cookie handling for the vault OAuth fix.
- No product behaviour changes in this item.

Source: [#356](https://github.com/dcolley/tourbillon/pull/356).

## Work in progress: internal developer tooling

An optional, internal-only Mastra Studio API surface was merged for the team's own debugging of agents. It is **off unless explicitly enabled**, is intended only for private internal networks, and is not a user-facing feature. Deployment checks are still in progress, so it should not be treated as available.

Source: [#357](https://github.com/dcolley/tourbillon/pull/357) (tracking [#348](https://github.com/dcolley/tourbillon/issues/348)).
