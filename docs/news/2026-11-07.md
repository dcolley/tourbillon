# Tourbillon weekly changelog — 7 November 2026

**Reporting window:** 31 October 2026, 09:40 through 7 November 2026, 09:40 GMT (Europe/London).

This week’s merged changes improve chat controls, agent identity, task-state clarity, run visibility and external harness integrations. This entry covers changes merged into `main`; it does not imply that every installation has upgraded or that every integration has been enabled.

## Chat controls and agent identity

### Choose how you send messages

Chat composers now support a choice between Enter to send and Ctrl/Cmd+Enter to send. In the latter mode, Enter inserts a newline. Composer hints reflect the selected mode, and the preference is saved per browser rather than synced between devices. Enter during IME composition does not send a message.

Follow-up changes harden keyboard handling, empty-draft behaviour, cross-tab preference listeners and the stopping state.

Sources: [#296](https://github.com/dcolley/tourbillon/pull/296), [#300](https://github.com/dcolley/tourbillon/pull/300), [#301](https://github.com/dcolley/tourbillon/pull/301), [#305](https://github.com/dcolley/tourbillon/pull/305), [#309](https://github.com/dcolley/tourbillon/pull/309), [#311](https://github.com/dcolley/tourbillon/pull/311), [#317](https://github.com/dcolley/tourbillon/pull/317), [#321](https://github.com/dcolley/tourbillon/pull/321).

### Personalise agent avatars

Agents can have a chosen avatar shape and colour, displayed in the assistant sidebar, chat header and agent page header. Agents without a custom choice retain the default initials avatar.

Activity and unread indicators are independent: working or waiting activity is shown on the avatar, while unread messages have their own row indicator. An agent can therefore be working and have unread messages at the same time.

Sources: [#297](https://github.com/dcolley/tourbillon/pull/297), [#302](https://github.com/dcolley/tourbillon/pull/302), [#306](https://github.com/dcolley/tourbillon/pull/306).

## Clearer tasks, issues and task state

### Separate chat tasks from board issues

Concierge instructions, skills and tool descriptions now explicitly distinguish private chat tasks from company board issues. Questions about promised chat work are directed to the task list; questions about board work are directed to issue tools. List requests are instructed to remain read-only.

The update also removes a stale reference to a nonexistent search tool and adds regression checks for the terminology and registered tool names. These are instruction and tool-description improvements, not a guarantee of every model response.

Source: [#349](https://github.com/dcolley/tourbillon/pull/349).

### More useful task listings and honest waiting states

The default task list now includes open work plus tasks completed in the previous 15 minutes. Full history remains available explicitly.

Task-tool transitions into a user-waiting state require a stated request for input. Runner failures are distinguished from genuine questions for the user, with clearer failure information rather than an invented request. Run-settle guards also improve handling when a controller stops before its work settles.

Source: [#345](https://github.com/dcolley/tourbillon/pull/345).

### Better queued-turn and restart handling

Queued user follow-ups now wait for the preceding run to settle before starting their own turn. When the concierge's task tool is asked to restart a parked task, it now requeues the task for execution and reports it as queued, rather than marking it as running.

Task-progress notification groundwork also landed. **End-to-end verification of an automatic, unsolicited reply through a real AgentController is still in progress. Automatic task notifications should not yet be treated as a verified working feature.**

Source: [#346](https://github.com/dcolley/tourbillon/pull/346).

## Run visibility and scheduler correctness

Approval-resolution wakes for the requesting agent no longer fail an assignee check intended for task-scoped work. Genuine assignee-mismatch skips are recorded as skipped rather than failed.

Skipped runs are surfaced in run counts and filters. Coalesced and cancelled outcomes also gain consistent counting, filtering and status mapping, while zero-count badges are hidden. Shared terminal-status checks and regression tests help keep those views aligned.

Sources: [#295](https://github.com/dcolley/tourbillon/pull/295), [#298](https://github.com/dcolley/tourbillon/pull/298), [#299](https://github.com/dcolley/tourbillon/pull/299), [#303](https://github.com/dcolley/tourbillon/pull/303), [#304](https://github.com/dcolley/tourbillon/pull/304), [#307](https://github.com/dcolley/tourbillon/pull/307), [#315](https://github.com/dcolley/tourbillon/pull/315).

## External harness integration

Direct-connection adapter code for Hermes and OpenCode was merged, with configuration validation, run dispatch and a shared capability-gated callback surface. These integrations require explicit configuration; their inclusion in the codebase does not mean they are enabled on every installation.

Subsequent changes add agent-to-agent messaging callbacks for configurations that advertise the capability. Calls use the agent’s assembled tool permissions rather than a separate unrestricted messaging path. Tool lookup accepts assembled keys or tool IDs while preserving those permissions.

The callback streaming surface buffers its frames until delivery completes; it is not live token-by-token streaming.
