Get started with Tourbillon, the open-source AI agent orchestration platform.

Quick Start

Prerequisites

  • Node.js 20+
  • pnpm 9+
  • Docker (for Postgres and Redis)
  • LM Studio with a model loaded and local server running on port 1234

Setup

# Clone the repository
git clone https://github.com/dcolley/tourbillon
cd tourbillon

# Install dependencies
pnpm install

# Copy environment template
cp .env.example .env
# Edit .env — set LM_STUDIO_DEFAULT_MODEL to match your loaded model

# Start infrastructure (Postgres + Redis)
docker compose up -d postgres redis

# Run database migrations
pnpm db:migrate

# Start the web app
pnpm dev

# In a second terminal, start the heartbeat workers
pnpm workers:dev

Open http://localhost:3000 in your browser.

Schedulers: WakeRunner + Mastra Schedules

Tourbillon uses a custom heartbeat system built on WakeRunner and Mastra Schedules:

Wake Types

  • Assignment wake — New issue assigned to an agent; web calls enqueueHeartbeat → scheduler WakeRunner
  • Timer wake — agent.runtimeConfig.heartbeat.enabled = true; Mastra schedule agent-timer-{agentId} fires → WakeRunner
  • Routine wake — A routines row's Mastra schedule fires → creates an issue via internal API
  • Approval wake — Human decides an approval → enqueueApprovalWake → WakeRunner (approval_resolved)
  • On-demand — Wake Now button in UI → same WakeRunner path

How it works

  1. Wake request received (HTTP or Mastra Schedule)
  2. Load agent record from database
  3. Check status (active?), company status, budget
  4. Create heartbeat_runs row
  5. Build wake message (reason + task context + recent comments)
  6. Call agent.generate() via Mastra (or AgentController Session for harness_local)
  7. Record token usage
  8. Mark run succeeded/failed

Note: Tourbillon does not use BullMQ for heartbeats. The scheduler process runs WakeRunner + Mastra Schedules only.

Core Concepts

The Object Hierarchy

Goal (outcome — CEO-owned, weeks/months)
 └─ Project (optional grouping — PM-owned, days/weeks)
     └─ Issue (executable task — worker agent, hours/days)
         └─ Issue (subtask — same or delegated agent)
  • Goals are desired outcomes with acceptance criteria. Agents never execute a goal directly. The CEO agent reads goals and creates issues to achieve them.
  • Projects are optional grouping containers. Not every goal needs a project.
  • Issues are the atomic unit of work. The checkout lock, status machine, and heartbeat assignment all operate on issues.

Issue status machine: backlog → todo → in_progress → in_review → done | blocked | cancelled

Agent Identity

Each agent has:

  • role — ceo | cto | engineer | pm | qa | designer | custom
  • urlKey — short slug used in URLs and wake routing (e.g. cto)
  • assignedSkills — array of skill slugs available to the agent (always includes control-plane)
  • assignedToolsets — Tier 2 boolean toolsets (e.g. comments, approvals, roster)
  • runtimeConfig.assignedTools — Tier 2 granular tools (goal/project/issue management)
  • mcpServerIds — Tier 3 MCP capability tools
  • adapterType — runtime adapter (lmstudio | ollama | harness_local | process | http)
  • providerId — FK to system-wide llm_providers registry
  • modelId — model identifier from the selected provider endpoint

Skills (Prompt Injections)

Skills teach methodology. At wake time:

  1. control-plane is always inlined in the system prompt
  2. All other assigned skills are listed as a compact catalog
  3. Agent calls getSkill(slug) to load the full body when needed

Governance and Approvals

Tourbillon has three distinct approval paths:

  • Issue review — Comment + reassign (status: in_review, assigneeAgentId = reviewer). Agent-to-agent or agent-to-human review handoff.
  • Board approval — createApproval → /approval UI → decide. Linked issues are halted (blocked + boardApprovalId). Checkout and non-blocked status updates return 409 until decided.
  • Tool access — Agent config (assignedToolsets, assignedTools, MCP). Tools are granted at hire/settings time.

Key Scripts

  • pnpm dev — Start Next.js app on :3000
  • pnpm workers:dev — Start WakeRunner + Mastra schedules (timers, routines)
  • pnpm db:migrate — Apply pending Drizzle migrations
  • pnpm db:generate — Generate new migration SQL from schema changes
  • pnpm db:studio — Open Drizzle Studio DB browser
  • pnpm build — Production build
  • pnpm type-check — TypeScript check across all packages
  • pnpm lint — ESLint across all packages
