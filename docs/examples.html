Examples

Real-world patterns for running agent teams with Tourbillon.

1. Heartbeat Team

Pattern: Multiple agents wake on schedule to check their inbox and execute assigned work.

How it works:

  • Each agent has a heartbeat timer enabled in runtimeConfig.heartbeat
  • WakeRunner receives timer events from Mastra Schedules
  • Agent calls getInbox to retrieve assigned issues
  • Agent calls checkoutIssue to acquire atomic lock
  • Agent executes work using assigned tools and skills
  • Agent calls updateIssue to report status and add comments

Use case:

CEO agent runs every 15 minutes, reviews goals, decomposes them into issues using the plan-to-tasks skill, and assigns work to engineers.

2. Assignment Wake and Handoff

Pattern: One agent completes work, assigns the next step to a different agent, triggering an immediate wake.

How it works:

  • Agent A completes an issue and sets status: in_review
  • Agent A calls updateIssue with assigneeAgentId set to Agent B
  • The system triggers an assignment wake for Agent B via WakeRunner
  • Agent B wakes immediately (no waiting for timer), calls checkoutIssue
  • Agent B reviews the work and either approves (status: done) or requests changes (status: in_progress, reassign back)

Use case:

Engineer completes a feature implementation, assigns to QA agent for testing. QA wakes immediately, runs tests, and reports results in a comment.

3. Hire an Agent with Board Approval

Pattern: CEO agent decides to hire a new agent but requires human approval before executing.

How it works:

  • CEO agent has the create-agent skill assigned
  • When CEO determines a new role is needed, it calls createApproval with type: hire_agent
  • Linked issues are automatically set to blocked status with boardApprovalId
  • Human reviews the request at /approval UI and decides (approve/reject)
  • On approval, WakeRunner triggers an approval_resolved wake for the CEO agent
  • CEO resumes execution, creates the agent, and updates linked issues

Use case:

CEO identifies need for a designer role based on backlog analysis. Creates approval request explaining why. Human approves. CEO proceeds to hire the designer agent with appropriate skills and toolsets.

4. Human Approval Gate for High-Cost Actions

Pattern: Agent needs to perform an irreversible or expensive action and must wait for human confirmation.

How it works:

  • Agent identifies a high-risk action (large spend, external API call, production change)
  • Agent calls createApproval with type: request_board_approval and links relevant issue IDs
  • All linked issues are halted (blocked + boardApprovalId)
  • Agent cannot checkout or update these issues to non-blocked status until approval is decided
  • Human reviews context in comments and approves or rejects
  • On approval, prior status is restored; on reject, issues remain blocked but halt ID is cleared

Use case:

Integration agent is about to call a production API that will charge $500. Agent creates approval with explanation of why the call is necessary. Human reviews logs, confirms budget, and approves. Agent resumes and makes the call.

Next Steps

These patterns are built into the control plane. To implement them:

  1. Create agents with appropriate role and assignedSkills
  2. Enable runtimeConfig.heartbeat for timer wakes
  3. Grant tool access via assignedToolsets and runtimeConfig.assignedTools
  4. Create goals and issues to seed the work queue
  5. Watch the heartbeat runs in the /jobs UI
